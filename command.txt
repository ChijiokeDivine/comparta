# Build Comparta Frontend UIs
## Context
You are working on Comparta , a DeFi-native financial OS on Circle's Arc L1. Stack: Next.js App Router (TypeScript 5), Tailwind CSS v4, Prisma client output to app/generated/prisma , NextAuth.js (Auth.js) with Credentials + Google providers, Manrope brand font, GSAP animations.
!important info: avoid too much text and information on the ui, make the text and content in the newly designed pages short and straight to the point, if text is need use tooltips. also prioritize whitespace and neatness above all
Current state:

- The backend is implemented. All domain logic, services, Prisma models, and REST API routes ( app/api/**/route.ts ) exist and are wired.
- The public landing page at app/page.tsx and the auth pages ( app/login/LoginForm.tsx , app/register/RegisterForm.tsx ) are built.
- No dashboard / authenticated UI exists. Sign-in and sign-up currently redirect to /dashboard which does not exist. This is your first deliverable.
- There is no shared app-shell, sidebar nav, or authenticated layout yet.
### Key files you must read before writing any UI code
Read these first to understand design language, auth pattern, and domain models:

1. app/page.tsx — home page (COMPONENTS, SPACING, COLORS, TYPOGRAPHY reference)
2. app/layout.tsx — root layout, Manrope font application, metadata
3. app/globals.css — CSS variables for the color system, and the btn-3d / btn-3d--neutral classes (use these for buttons)
4. app/login/LoginForm.tsx — current auth UI style reference (spacing, rounding, focus rings, palette)
5. middleware.ts — route protection : the matcher here lists every authenticated route prefix you must build under. Create pages that live exactly under these prefixes so the middleware enforces auth on them. The matcher is: /dashboard/:path* , /wallet/:path* , /invoices/:path* , /payroll/:path* , /savings/:path*
6. prisma/schema.prisma — models, enums, their relations and invariants. The field names, enum values, and status lifecycles here are the source of truth for every form and status badge you render.
7. app/api/**/* — walk the full app/api directory tree; every route file you find has an HTTP contract (JSON fields, enums) you MUST match exactly. Example: app/api/transfers/send/route.ts is the send-payment endpoint; app/api/invoices/[id]/send/route.ts is the "send invoice" action; etc.
8. lib/insights/dashboard/queries.ts — pre-written dashboard analytics queries (use these to populate the dashboard's KPIs and charts; do not invent new aggregations).
9. lib/auth/kyb-gate.ts — the KybStatus gate. Most financial write-actions require kybStatus === APPROVED per the Prisma Organization model. Build the UI to reflect this: disable financial buttons + show a KYB status banner when an org is still PENDING (Google sign-up creates an org in PENDING KYB state per the CompartaAuthAdapter, see lib/auth/auth.ts ).
10. lib/auth/canManageBucket.ts — role-based gate. Operations on buckets, allocation rules, payroll schedules, savings rules are restricted to OWNER/ADMIN, not MEMBER. Your UI should reflect this in the nav and with disabled states for MEMBER roles.
### Style directive
Use the font (Manrope), color palette, spacing scale, rounded corners, and the btn-3d button component style exactly as they are used in the home page app/page.tsx . Do not invent a new color system or a new component system.

## GENERAL FRONTEND RULES (do not write a new design system — obey these)
- Use the same font (Manrope) that is loaded in the home page app/page.tsx and layout.tsx .
- Use the exact same color palette, spacing scale, border radii, and btn-3d / btn-3d--neutral button style used in app/page.tsx (navy #0B1E3F, blue #2A5CE6, gray text #7C8CA6, borders #E5E9F2, card white, divider #F2F4F8 — as you see in LoginForm/RegisterForm).
- All money fields: user enters USDC as a decimal string. Convert to/from bigint (6 decimals of smallest unit) at the API boundary. Never use parseFloat , number , or toFixed in a way that loses cents. Use a dedicated helper similar to the app/invoices/_components/format.ts that already exists.
- Forms: label + input pattern same as LoginForm (rounded-xl, 12px horizontal padding, focus:border-[#2A5CE6]).
- Server components by default (App Router); use "use client" only where interactivity requires it (forms, state, hooks). Keep page shells as RSC and put forms inside smaller client components.
- Pagination: use cursor/limit-style where the API already does.
- Loading states: inline skeletons matching the content shape, not spinners where avoidable.
- Error handling for API calls: show inline error banner below form using the same styling as LoginForm's bg-red-50 border-red-100 text-red-700 rounded-xl .
- Optimistic UI: after POST-ing a create, route to the list page and invalidate the cache with router.refresh() or Next.js cache tags if the API exposes them.
- Accessibility: buttons have visible focus rings (match 2px blue focus style), labels always, form errors announced with role="alert" , icons with aria-labels.
- Respect role-based gating from canManageBucket.ts :
  - OWNER/ADMIN → full actions
  - MEMBER → read-only (buckets, payroll-schedules, allocation, savings rules non-editable)
- Respect KYB gating from kyb-gate.ts :
  - KybStatus.PENDING → show big sticky banner across the top of every financial page: "We're reviewing your organization. Most actions are disabled until approved." + DISABLE financial CTAs (transfer, create invoice, approve payroll, new payment link, redeem yield, start DCA). Keep navigation and dashboard visible.
  - APPROVED → normal behavior
  - REJECTED → banner "Your KYB was rejected. Contact support." + all financial writes disabled.
